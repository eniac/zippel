Paper: Zippel: A Language, Compiler, Runtime, and Analyzer for ZK Proof Systems (IEEE S&P 2027 submission).

One row per central claim of the paper's introduction, pointing at the code that is evidence for it. Links are relative to this file — open artifact/index.html from a clone of the repository (or inside the Docker image under /zippel/artifact/). Each code anchor names the exact declaration to search for in the linked file (Ctrl-F), because line numbers drift. How to build the image and run the three experiments is in README.md.

Known deltas from the submitted paper (full accounting in README.md):
(1) Completeness count. §9.3 says "Zippel can automatically verify 20 of them (66.7%)"; the corrected count is 18 of 30. Minus 5: the whole HyperPlonk family and Dekart were false positives from a bug that has since been fixed. Plus 3: Groth16, KZH and Bulletproofs (ipa) each had a where clause missing required constraints, now fixed.
(2) LoC drift. Figure 6 and the Zippel LoC column of Figure 7 have moved: zippel-fmt did not exist at submission time and reformatting the examples changed line counts on its own, and several where clauses were revised (see (1)). Native baseline LoC are unchanged and Zippel stays shorter than native for all nine benchmarked systems.
(3) Figure 7 Hyrax. The submitted prose claimed a prover speedup up to 6.1× (1 thread) and verifier 3.4×. Corrected during review to 1.11× prover at 1 thread and 3.30× verifier; the prover ratio dips between 1 and 2 threads. This is expected and has been discussed with the paper's reviewers.
(4) Figure 7 Spartan. The primary spartan row measures 0.29×–0.72× prover speedup, below the paper's claimed "on par" 0.76×–1.49×: that baseline is Microsoft's libspartan, which uses curve25519-dalek and hand-optimized code rather than arkworks. The added spartan (ark-spartan) row compares against the same curve and arkworks version and gives 0.98×–1.51× prover, 0.99× verifier — matching the paper. The camera-ready will report both rows.
